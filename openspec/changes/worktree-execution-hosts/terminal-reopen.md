# 打开已有原生终端即恢复

用户于 2026-11-14 明确要求添加此功能。复用本变更既有主机路由、原生身份和目录约束。

- 打开应用、工作区或已有 Agent 终端时，活宿主直接接回；死宿主按保存的原生会话 ID 恢复，不需要先点重新启动。
- 允许在新的打开意图下恢复已明确停止的原生终端；停止之后继续停留或被动轮询不得立刻拉起。只读历史始终只读。
- 用户进一步明确全部 Agent 均需要：Codex、Claude、Gemini、OpenCode、OMP、Kimi、ZCode、MiniMax，按各自原生命令恢复。没有 ID 时不得猜测最近会话，保留原生选择/错误入口。
- 请求仍校验宿主死亡、工作区归属、任务类型、权限及原参数；初始任务不重放；失败不无限重试。远端不回落本机。
- 给定已停止的绑定会话，重新打开后应恢复同一原生对话，输入只送到新宿主；给定运行会话，重开不创建进程；给定刚停止且仍可见的会话，轮询不恢复，下一次打开才恢复。

验证和交付记录见 `_bmad-output/initiative-velella-standards/plan-terminal-reopen.md`；源码/fixture 检查不替代真实模型和业务 UAT。正式 profile 与其他运行进程保持原状。

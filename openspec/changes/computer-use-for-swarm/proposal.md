# Computer Use 给鱼群使用（本地 Windows）

用户确认需要 Velella 的鱼能通过截图、鼠标和键盘观察并操作这台电脑。MiniMax Code 作为实现引擎，BMAD 负责计划/构建/审查方法。现有鱼群 MCP 配置是集成点，不是已实现的桌面控制器。

交付一个**显式启用**的本地 Windows MCP 服务与一份生成的鱼群目录清单，并给出可执行的启用/使用/停止路径。复用官方 Python MCP SDK、Pillow 的采集与编解码，以及 Windows 原生输入 API。保留现有鱼群角色选择与工具白名单。不新增 Agent 运行时，不改动界面。

## 变更范围

- `tools/computer-use/`：独立可安装的 MCP 服务（`server.py`、`windows.py`、`control.py`、`catalog.py`）、本地锁定依赖（`uv.lock`）、单元与协议测试、中文 `README.md` 与 `DEVELOPMENT.md`。
- `scripts/verify-computer-use.py`：协议模式走真实鱼群中继并使用固定运行时与临时数据目录；原生模式只允许操作自有夹具窗口。
- `openspec/changes/computer-use-for-swarm/`：本提案。

## 边界

**始终**：在隔离的候选目录中开发；不触碰原有脏检出、实时配置、CLI 设置与运行进程；不发布、不安装、不迁移。观察与输入分离：控制能力必须通过既有鱼群设置被明确选择并确认。一台 Windows 桌面同时只允许一个控制进程（跨鱼角色、跨工作流）；租约有界、过期可回收、断开或崩溃即释放、可本地停止；不会把另一条鱼的租约悄悄转交。这些是协作式流程控制，不是针对同用户原生程序的安全沙箱。

**绝不**：为所有鱼自动开启电脑输入；把任意 shell 命令暴露为工具；改写剪贴板实现文本输入；把远程角色静默路由到本地桌面。不在本候选中实现 macOS/Linux/远端版本。测试期间不做真实账户的业务操作。

## 验收

- 新的目录清单被载入并为某个本地角色显式确认后，只有被选中的工具通过真实鱼群外部 MCP 中继暴露；初始化、列举与调用通过，且不修改用户配置。
- 在自有测试窗口上点击、拖拽、滚动、输入 `鱼群 Computer Use 你好` 并使用组合键后，夹具状态与后续截图能证明效果；不会把输入发送到真实用户应用。
- 两个独立服务进程同时请求控制时只有一个注入输入；拥有者退出、租约过期与本地停止都能释放/撤销控制。
- 高熵多屏采集经真实中继返回时，序列化整帧低于 1 MiB，坐标映射正确；不支持的原生条件显式失败。
- 缺少输入启用、租约过期、非法输入或桌面不可用时返回错误，不注入输入，也不谎报完成。

## 状态

MiniMax Code 在隔离候选中实现服务与初始协议检查；root 审查补齐缩放坐标、显式输入开关、凭据轮换、动作互斥、拖拽校验/释放、桌面可用性和原生验收脚本。验证结论以固定源码的实际回执为准；本提案不代表部署、在线或业务 UAT。负原点的多屏高熵图像使用合成夹具覆盖，真实硬件测试范围以回执说明为准。

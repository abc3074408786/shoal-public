# GitHub scan-to-connect

Outcome: the new GitHub connection entry presents an account/repository flow instead of a long form. Existing CLI login opens repository selection. Otherwise the user requests a QR code, scans the GitHub verification URL, enters the separately displayed device code and approves GitHub CLI. Velella confirms the CLI result, lists repositories, and saves the selected source through the existing source connection contract.

Acceptance: QR is generated locally and decodes to https://github.com/login/device; it never contains a token. No authentication starts on mount. Existing login, waiting, success, cancellation, timeout, denied/failed authorization and missing CLI have explicit states. Close/cancel stops only the owned login process. CLI stdout/stderr and credentials never reach the UI or logs. Duplicate starts are idempotent. Existing manual GitHub/enterprise/token connection and other providers remain available. Repository pagination and connection failure are recoverable without restarting authorization. QR, copy-code and browser alternatives work with keyboard and narrow windows. Browser and isolated native evidence remain separate from real user authorization/UAT.

Critical path: bounded gh login process ownership and parsed device-code contract -> local QR and account/repository UI -> behavior and QR decoding tests -> fixed native candidate. The installed task-flow version is protected; its fixed source is artifacts/task-flow-20261019/source-fff192e39316. New deployment requires its own concrete approval.

Source contracts (read-only, gh v2.96.0):
- https://github.com/cli/cli/blob/v2.96.0/internal/authflow/flow.go (DisplayCode and noninteractive BrowseURL)
- https://github.com/cli/cli/blob/v2.96.0/pkg/cmd/auth/login/login.go (Interactive and environment-token checks)
- https://github.com/cli/oauth/blob/v1.2.2/oauth.go (device first, webapp fallback)
- https://github.com/cli/oauth/blob/v1.2.2/oauth_device.go (verification URI and server-governed timeout)
- https://github.com/cli/cli/blob/v2.96.0/pkg/cmd/auth/shared/login_flow.go (credential storage and successful exit)

GitHub.com only for the QR path. Enterprise and other providers use their existing manual connection paths. Device-code expiry is controlled by gh/server; an additional bounded local wait is a client timeout, not a claimed code lifetime. The account shown on GitHub is GitHub CLI. No app registration, auth token copying, automatic remote writes or authentication-dialog automation is part of verification.
